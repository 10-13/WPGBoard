# АТЛАС: правила работы

## Архитектура и сохранность данных

- Ядро остаётся headless. Предметная логика принадлежит расширениям; игровые
  изменения проходят через экшены и историю ядра.
- UI-примитивы должны переиспользоваться расширениями. Не копировать отдельную
  реализацию одинакового дерева или списка в каждый модуль.
- Сборка `python3 build.py` создаёт автономный `dist/index.html` без внешних
  ресурсов. Пользователь просил работать локально, без публикации в Sites.
- Не добавлять демонстрационные данные в пользовательскую партию. Проверять
  интерфейс на отдельной партии и отдельном ключе автосохранения.
- При пересборке пользовательского HTML сохранять встроенные данные и `saveKey`,
  чтобы новая версия подхватила актуальное автосохранение этого файла. Не заменять
  его старым JSON или демонстрацией. Изменять ключ только при отдельном экспорте
  самостоятельной копии партии.

## Утверждённый стиль интерфейса

Эталон согласован с пользователем в макете `statistics-tree-preview.html`.
Пользователь согласовал перенос на весь интерфейс: оболочку, окна, вкладки,
нации, ресурсы, историю, редакторы, меню, подсказки и номера провинций на карте.
Новые расширения должны сразу использовать эти правила.

1. Один моноширинный шрифт: `Menlo, Consolas, "Liberation Mono", monospace`.
   Один размер — **10 px** — для всех элементов интерфейса: подписей,
   значений, категорий, кнопок, полей, счётчиков, вкладок и элементов управления.
   Общие CSS-переменные: `--atlas-font`, `--atlas-font-size`, `--atlas-step`.
   Не задавать отдельные размеры для заголовков, `small`, иконок из текста,
   полей, пунктов меню, статусов или мобильной версии. Canvas-номера берут
   типографику из вычисленного стиля карты.
2. Курсив, наклон, растяжение и другие сильно меняющие форму модификаторы
   исключены. Цвет, насыщенность и зачёркивание допустимы.
3. Базовый вертикальный шаг строки данных — **16 px**. У категорий тот же шаг
   и нет дополнительных вертикальных полей. Разделение блоков кратно 16 px.
4. Длинные названия, строки, описания и JSON переносятся полностью. Не прятать
   данные многоточием, `line-clamp` или горизонтальным обрезанием. Две строки
   занимают 32 px, три — 48 px и т. д.; соседняя строка начинается после самого
   высокого столбца. Перенос должен работать и после изменения ширины окна.
   Это касается также названий наций, групп, вкладок и многострочных кнопок.
   Нативные поля ввода сохраняют обычное редактирование и прокрутку текста.
   Отступ заголовка вкладки закреплён на `.tab-label` (8 px); активное состояние,
   фокус и нажатие не должны менять отступ, рамку или ширину вкладки.
5. У обычной строки — одинарная линия от названия к значению. Горизонтальных
   разделителей под строками нет. У категории — двойная линия после названия
   до края. При переносе линия привязана к первой строке текста.
6. Группы начинаются сразу с названия, без треугольника и пустого места под него.
   Все группы, включая корневые, одинаково меняют цвет: закрытые серые
   `#a7bdc8`, раскрытые золотистые `#c5ba9d`. Сохранять сворачивание мышью и
   клавиатурой, фокус и доступность native `details/summary`.
7. Отступ каждого уровня вложенности — **21 px** (вместе с направляющей).
   Горизонтальная вложенность сохраняется; её нельзя путать с вертикальными
   промежутками между строками.
8. Нижней легенды «значение / категория» и её разделителя нет.

Общие примитивы: `packages/ui/data-view.js`, стили `packages/ui/data-view.css`.
Базовая типографика и размеры всех контролов находятся в `style.css`.
Метаданные, статистика, нации и ресурсы используют общие строки и группы;
не дублировать их реализацию внутри расширений. Класс `atlas-data-scope`
может обозначать область данных, но не задаёт отдельную тему окна.
У кнопок внутренняя рамка: она не добавляет 2 px к многострочной высоте.
Однострочные поля имеют высоту 16 px; внутренний line-height компенсирует
нативную рамку. Для цветовых образцов, чекбоксов и захватов ресайза допустимы
свои геометрические размеры, не меняющие типографику или шаг строк.

## Проверка

- `node --test tests/*.test.cjs` — проверки ядра, расширений и UI-контрактов.
- Проверять перенос длинного названия и длинного значения, включая текст без
  пробелов и JSON, при узком и широком окне. Видимые строки должны иметь высоту
  16 × N px; значения и названия должны оставаться доступны полностью.
- Проверять открытие/закрытие корневой и вложенной группы, редактирование
  метаданных и сохранность расчётов. Для простых визуальных изменений достаточно
  проверки реального DOM и скриншота; не добавлять тесты, повторяющие CSS.
- При общих изменениях UI проверять нации, группы, дипломатию, ресурсы и их
  формы, историю, модули, файловые формы, контекстное и вложенное меню.
  Проверять узкое окно 220 px и адаптивную оболочку; возвращать временный
  viewport браузера к исходному после проверки.

## Ввод регионов и оболочка

- Любое действие по клику на регион проходит через `ui.regionClicks`.
  Пассивных подписок может быть много, активный обработчик — максимум один.
- Активные подписки расширений создавать через `tab.onRegionClick` с
  `mode: 'active'`. Закрытие вкладки/окна снимает подписки; перенос сохраняет их.
  Не восстанавливать прежний обработчик автоматически и не обходить диспетчер.
- Прикладных клавиатурных шорткатов нет. Не возвращать `ctx.tool`, `ui.tools`,
  переключатель «Клик» или верхний бар с названием, веткой и модулями.
  Верхняя часть — только строка меню; модули доступны через «Вид → Окна → Расширения».
- Верхние пункты в фиксированном порядке: «Файл», «Вид», «Мир», «Инструменты».
  `TreeMenu.rootOrder` задаётся опцией конструктора; приоритет команды внутри
  раздела не должен переставлять корни. «Файл» сохраняет прежние команды.
- Общий список окон — «Вид → Окна». Открыватели основных окон расширения
  регистрировать через `ctx.windowMenu({id, label, handler, enabled})`:
  префикс ID, путь и `AbortSignal` добавляет UI. Они исчезают с модулем/хэндлером.
  Создание и редактирование объектов остаются предметными командами; окна
  инструментов также можно открывать из соответствующего раздела «Мир».
- «Мир» содержит «Нации», «Регионы», «Ресурсы». «Инструменты» содержит
  «Выделение», «История», «Данные → Мета / Статистика». Новые команды сразу
  регистрировать в подходящем поддереве, не возвращать прежние верхние пункты.
  Структуру контекстного меню провинций это изменение не затрагивает.

## Выделение и пакетные команды

- Общий временный выбор — `ui.regionSelection` из UI-библиотеки. Клик заменяет
  выделение одной провинцией, **Shift + клик** добавляет/удаляет провинцию.
  Этот модификатор мыши явно согласован пользователем; прикладных клавиатурных
  шорткатов по-прежнему нет. Shift + клик обновляет пассивных наблюдателей,
  но не запускает активное редактирование и не выключает выбранную кисть.
- Правый клик по участнику группы сохраняет группу; по другой провинции —
  выбирает её одну; по пустому месту — снимает выделение. Временные слои
  выделения и набора статистики не попадают в PNG и историю игры.
- `ui.tileMenu` — `TreeMenu({regionContext: true})`. Регистрация `batch: true`
  передаёт `handler(regionIds, context)` замороженный массив ID и доступна для
  любого непустого выбора. По умолчанию `batch: false`: команда видна только
  для одной провинции и получает `handler(regionId, context)` с числовым ID.
  `when`/`enabled` получают контекст с `regionIds`, а `id` равен `null` для группы.
  Обычный `TreeMenu` сохраняет `handler(context)`. Открытое меню хранит снимок
  ID; отключение обработчика по-прежнему снимает регистрацию автоматически.
- Набор статистики принадлежит расширению и независим от общего выбора.
  Добавление/исключение — пакетные команды контекстного меню; не возвращать
  активный сбор тайлов или потайловый список. Смена выделения не меняет набор.
- Общие кнопки и подсвечиваемые переключатели — `AtlasUI.controls.button` и
  `createSwitch`; те же функции доступны в `AtlasUI.dom`. Использовать их в
  новых расширениях. `switch.checked` отражается в `aria-checked`; внешнее
  присваивание не вызывает callback. Сохранять типографику 10 px и шаг 16 px.
- Выделение, наведение и набор статистики рисуют контуры через общий
  `AtlasUI.drawRegionSet`. Учитывать всех четырёх соседей пикселя: одних концов
  RLE-строк недостаточно для верхних/нижних границ, выемок и отверстий.
  `offsetX`/`offsetY` позволяют рисовать тот же контур в обрезанном Canvas наведения.
- «Добавить соседние провинции» расширяет общий выбор ровно на один слой,
  сохраняя выбранные провинции. «Эрозия выделения» одновременно удаляет один
  крайний слой: провинции у невыделенного соседа, воды или края карты.
  Оба действия локальные, не меняют статистический набор и историю.
- Соседство вычисляет headless `ProvinceTopology` (`packages/core/province-topology.js`)
  по индексу и исходному RGBA: общая граница, четыре направления, без диагональных
  касаний. Нулевые пиксели чёрных штрихов соединяются лучами до 4 px; лучи не
  проходят через воду и промежуточную провинцию. `viewport.getTopology()` строит
  и кэширует граф по требованию, сбрасывая его при загрузке карты.

## Именованные регионы и контекстное меню

- Группы наций удалены из интерфейса и API наций. Пользователь явно отказался
  от их переноса: не читать `nations.groups`/`groupAssignments` как новые регионы.
  Прошлые записи истории остаются историей; не переписывать их.
- Именованные регионы — независимое расширение `regions` с headless-моделью
  `extensions/regions-model.js` и UI `extensions/regions.js`. Данные лежат в
  `meta.regions.{items,assignments}`. Одна провинция входит в один регион;
  создание с составом, переименование, добавление/исключение и удаление проходят
  через экшены ядра. Нации и регионы не зависят от включения друг друга.
- `state.regions` и `regionIndex` по-прежнему описывают геометрию провинций;
  не путать их с пользовательскими регионами `RegionsModel`.
- Корни контекстного меню: «Мир», «Провинция», «Прочее».
  «Мир → Владения» принадлежит нациям, «Мир → Регионы» — регионам;
  «Провинция» содержит только одиночные свойства, метаданные и ресурсы;
  «Прочее → Статистика» — пакетные добавить/исключить/задать область.
- «Очистить регион» исключает выделенные провинции из их регионов, не трогая
  остальные провинции или названия. «Задать область» заменяет набор статистики.
  Переходы «К нации»/«К региону» выбирают сущность в её окне без включения кисти.
- «Информация» — пакетная команда: уникальные нации выбранных провинций
  открываются вкладками одного окна, без дубликатов и свободных территорий.
- Модуль регионов регистрирует один оверлей `regions:boundaries` («Регионы»):
  внешний контур состава и название. Между провинциями одного региона шов не
  рисуется; вода не соединяет несвязанные территории. Геометрия и точка подписи
  вычисляются в headless `region-geometry.js`, Canvas — в `region-overlay.js`.
  Точка подписи находится на одной из провинций региона; текст использует
  общую типографику 10 px / 16 px и переносится полностью.

## Оверлеи и локальное отображение

- `state.overlays` — headless-реестр ядра (`packages/core/overlays.js`).
  В нём только определения и настройки композиции, без Canvas/DOM.
- Пользователь уточнил границу: **отображение не версионируется**. Видимость,
  порядок, номера провинций и подсветки не создают экшены, не попадают в
  `meta`, `params`, историю/ветки или экспорт партии JSON/HTML. Существование
  и свойства игровых объектов по-прежнему меняются через экшены ядра.
- Локальные настройки сохраняет браузерный адаптер отдельно от партии:
  ключ IndexedDB `['overlay-preferences', saveKey]`. Параметры конкретного слоя
  хранятся в `state.overlays.getOptions(id)` / `setOptions(id, options)` и там же
  сохраняются отдельно от игры. Формат настроек версии 1 допускает `options`;
  прежние файлы без этого поля сохраняют совместимость. `state.load`, переключение
  веток и отмена не заменяют настройки отображения. Для QA нужен отдельный
  `saveKey`, чтобы не менять пользовательские предпочтения.
- Расширения рисуют через `ctx.overlay({id, title, order, visible, exportable})`:
  возвращаются `id`, `canvas`, `context`, `visible`, `setVisible`, `dispose`.
  Префикс модуля и его `AbortSignal` добавляются автоматически. `ctx.layer`
  остаётся совместимым псевдонимом. Не вводить отдельные скрытые Canvas-слои
  или собственный порядок `z-index` в расширениях.
- `OverlayRegistry.list` идёт от заднего плана к переднему; окно «Вид → Окна → Оверлеи»
  показывает обратный порядок. Все мировые и экранные оверлеи компонуются
  одним UI-адаптером `packages/ui/overlays.js`, включая номера и подсветки.
  Исходная карта остаётся основой под ними.
- PNG использует тот же порядок и видимость, пропуская `exportable: false`.
  Подсветки наведения, выделения и набора статистики временные и в PNG не входят.
  Экранному экспортируемому оверлею нужна функция `exportDraw(context)` для
  отрисовки в координатах исходного PNG. Сохранять резкие пиксели мировых слоёв.
- У оверлея регионов один экранный Canvas с контурами и подписями; его приватный
  offscreen bitmap — только производный кэш пиксельных контуров, не отдельный
  слой карты. Изменение состава/названия и отмена обновляют рисунок. Видимость
  управляет одновременно границами и названиями на экране и в PNG.
- Отключение модуля удаляет его определения и Canvas, сохраняя локальные
  предпочтения по стабильным ID для следующего включения. Скрытый слой не
  удаляет объекты и продолжает получать актуальные данные. Переключатели
  номеров/подсветки набора используют реестр, а не отдельные флаги.

## Ресурсы и чертежи

- Каталог и расчёт сырьевой стоимости — headless-часть расширения ресурсов:
  `resource-catalog-data.js`, `resource-catalog.js`. Интерфейс отдельно в
  `resource-catalog-ui.js`; деревья и строки используют общие data-view примитивы.
- Чертёж содержит объёмы `inputs`/`outputs`, название и описание. У него нет
  денег, времени, мощности или выпуска за ход. Производительность принадлежит
  отдельному предприятию. Каталог сам не размещает объекты на карте.
- Базовый набор версии 1 — неизменяемый шаблон игровых пропорций: 30 ресурсов
  и 23 чертежа. Отсутствующая настройка партии использует этот шаблон без экшена
  при запуске или просмотре. Не менять его смысл для старых партий молча.
  Первое редактирование копирует весь набор в `meta.resources.catalog`;
  последующие изменения — экшены `resources.catalog.*`, с историей и экспортом.
- ID ресурсов стабильны; входы и выходы ссылаются на них, а не на имена.
  Объёмы положительные, допускают дроби; выходов может быть несколько.
  Удаление используемого ресурса запрещено, пока на него ссылаются чертежи.
- Стоимость дерева — исходное сырьё для заданного объёма. Все вложенные
  переделы масштабируются пропорционально, одинаковое сырьё суммируется.
  Природный ресурс завершает ветку, если пользователь не выбрал его синтез.
  Альтернативы и объём расчёта — локальное состояние просмотра, не экшены.
- Для нескольких выходов полный вход относится на выбранный продукт;
  сопутствующие выходы показываются явно, без вычитания из соседних ветвей.
  Не скрывать эту оговорку в интерфейсе. Пропавший чертёж, цикл или предел
  раскрытия — явная незавершённая ветка, а не бесплатное природное сырьё.

## Географическая основа 1936

- Авторский набор `assets/geography-1936.json` содержит подписи всех 4587
  провинций и 162 географических региона для исходного пиксельного индекса.
  Это игровая основа с историческими названиями, не точная реконструкция
  административных границ 1936 года. Крошечные островки могут иметь одинаковые
  описательные подписи; канонический ключ — ID провинции.
- `tools/build-geography-1936.cjs` проверяет SHA-256 индекса, полноту ID и ссылок
  на регионы, затем создаёт отдельные `outputs/atlas-1936.html` / `.json`.
  Не подменять этим набором пользовательскую партию, её saveKey или обычный
  `default-project.json`. Применение данных — один обратимый экшен ядра;
  отображение и оверлеи в него не входят.
- `country`, `admin`, координаты, GeoNames ID и метод в справочном файле служат
  для происхождения названий. Современные справочные коды стран не задают
  исторические владения. В игре используются `meta.nations.names` и
  `meta.regions`; исторические источники и оговорки — `meta.geography`.
- Сохранять атрибуцию GeoNames (CC BY 4.0), происхождение Natural Earth и
  оговорки из `outputs/atlas-1936-info.md` при распространении производных основ.

## Экономические расстановки 1936

- `assets/resource-import-1936.json` сохраняет 69 исходных маркеров из
  «ресурсы.html», SHA-256 источника и привязку к провинциям. Это самостоятельная
  версия только с бонусами +100% к местной добыче; базового выпуска в ней нет.
- Независимая историческая игровая версия использует
  `assets/economy-1936-profiles.json` (21 профиль, явные назначения всех 162
  регионов) и `assets/economy-1936-sites.json` (69 сырьевых точек, 195 промышленных
  узлов по всему миру, решения по исходным точкам и ссылки). Поздние и
  неподтверждённые точки не переносить безусловно. Коэффициенты условные;
  не представлять их как исторические тонны, запасы или архивные оценки.
- Базовый выпуск есть во всех 4587 провинциях; площадь влияет на мощность.
  `resource.role: 'baseline'` обозначает фоновый провинциальный выпуск. После
  перехода к пиксельным блокам каждая такая запись тоже получает пиксель своего
  ресурса, наравне с отдельными предприятиями. Это тип игрового объекта,
  не сохранённая настройка видимости.
- Каждое месторождение усиливает реально существующую добычу своего сырья.
  Каждый промышленный узел содержит конкретные предприятия по неизменённым
  базовым рецептам и локальную инфраструктуру (+50% выпуск, −10% расход сырья
  на единицу). Количества, рецепты и приоритеты редактируются обычным UI.
- `python3 build.py`, затем `node tools/build-economy-1936.cjs` собирают
  `outputs/atlas-1936-import.html/.json` и `atlas-1936-economy.html/.json` из
  географической основы. Ключи автосохранения у версий отдельные. Исходную
  географию, пользовательские партии и файл из Downloads не заменять.
  Этапы размещения — обратимые экшены ядра; сборщик проверяет undo/redo,
  полноту провинций, входы предприятий и ресурсные балансы всей карты.
- Большие расчёты сохраняют все предприятия в API и дереве; после 200 строк
  список загрузки разбивается на папки по 100 в том же порядке приоритетов.
  Общий `renderDataTree` монтирует закрытые ветки только при раскрытии и
  учитывает `defaultOpen: false`. Ядро допускает до 100000 узлов на считалку;
  не убирать защитный предел и не обрезать данные ради отображения.

## Оверлей ресурсов

- Обычный слой `resources:richness` («Богатство ресурсов») принадлежит модулю
  ресурсов; по умолчанию выключен, располагается над владениями и под маркерами.
  Легенда доступна в «Вид → Окна» и «Мир → Ресурсы». Её общий переключатель
  управляет той же видимостью, что и окно оверлеев, не изменяя другие слои.
  Пользователь выбрал обычное включение/выключение; не вводить режим solo.
- Окрашивается каждая провинция отдельно. Источник — результат
  `state.statistics.calculate([...state.regions.keys()]).get('resources')`:
  наибольший потенциальный местный выпуск с бонусами, до расходов и ограничений
  снабжения. Выпуск одного ресурса из разных видов деятельности суммируется.
  Разные единицы не объединяются; численные объёмы сравниваются без конверсии.
  Без положительного выпуска провинция остаётся прозрачной; бонусная точка
  сама не создаёт выпуск. При равенстве побеждает первый ресурс.
- Для каждого ресурса/единицы минимум и максимум определяются по **всем**
  провинциям с положительным выпуском, после суммирования видов деятельности,
  даже если на провинции лидирует другой ресурс. Минимум окрашивается базовым
  RGB × 0.5, максимум — смесью RGB и белого 50/50; промежуточные значения
  линейно интерполируются. Если минимум равен максимуму, использовать базовый
  цвет. Сами пиксели предприятий сохраняют постоянные цвета.
- Легенда показывает границы, пять градаций (одну при одинаковом выпуске),
  число окрашенных провинций / число провинций с выпуском и общие переключатели.
  Выключенный ресурс исключается из выбора главного: провинция переходит к
  следующему включённому по объёму или остаётся прозрачной. Шкалы не сужаются
  при фильтрации. Скрытые ключи лежат в options `resources:richness`, не в meta.
  Фильтрация проецирует кэш результатов и не запускает заново расчёт экономики.
- Пользователь заменил палитру по порядку появления на постоянные цвета.
  `resource-colors.js` задаёт явный HEX для каждого из 30 базовых ID. Для новых
  ресурсов цвет воспроизводится по стабильному ID каталога; для свободных
  названий — по нормализованной строке. Единицы и порядок появления цвет
  не меняют. `ResourceCatalog.color(idOrName)` даёт ту же палитру, что раскраска,
  легенда и маркеры. Цвета — статичная визуальная библиотека, не экшены и
  не поля партии; базовый каталог пропорций версии 1 остаётся неизменным.
- `resource-richness.js` — headless-проекция результатов; `resource-overlay.js` —
  рисование и окно легенды через общие контролы/data-view.
- Слой использует точные RLE-маски провинций: вода, отверстия и исходные линии
  остаются нетронутыми, сглаживания нет. Видимый слой входит в обычный PNG
  вместе с остальными оверлеями в заданном порядке. Закрытие легенды не меняет
  видимость; выключение модуля удаляет слой и окно, сохраняя игровые объекты.
- Расчёт ленивый: первое открытие легенды/включение слоя, затем кэш до изменения
  данных. Повторный клик переключателя не должен повторять расчёт всего мира.


## Прототип ресурсных маркеров

- Пользователь утвердил **два пиксельных прямоугольника** вместо кружков и треугольников.
  Верхний содержит производства, нижний — ресурсные точки/улучшения. Между ними
  ровно один пиксель зазора. Если есть только один тип объектов, лишнего блока
  и зазора нет. Один объект — один пиксель исходной карты, включая базовый выпуск;
  одинаковые цвета идут подряд при построчном обходе каждого блока. Не объединять
  несколько предприятий в один пиксель и не менять их расчётные приоритеты.
- `resource-markers.js` подбирает целочисленные размеры под соотношение сторон
  bbox провинции и центрирует блоки около `region.anchor`. Площадь каждого блока
  равна числу его объектов: без фиктивных ячеек и масштабирования.
  **У каждого блока внешняя обводка 1 px**, цвет `#101c22`; зазор 1 px считается
  между внешними краями обводок. Проверка вместимости учитывает обе рамки.
  Цвет берётся из общей палитры; общий бонус `*` — белый.
- Весь общий прямоугольник, включая зазор, проверять по **реальной маске** индекса.
  При необходимости искать ближайшее к центру положение, учитывая отверстия,
  воду, соседние провинции и несвязанные части. Если ни один вариант целиком
  не помещается, скрывать оба блока. Не обрезать их и не сжимать до общих пикселей.
  Местоположения кэшируются по неизменяемому индексу; игровые данные не меняются.
- Отдельные `outputs/resource-markers-preview.html` и
  `resource-marker-layout-preview.html` показывают новый вариант; примеры —
  реальные провинции #823, #1347, #1072, с увеличением блоков ×16.
  У интерактивного прототипа свой saveKey. Основные пользовательские HTML/JSON
  пока содержат прежний выпуск интерфейса. При переносе кода в основные страницы
  точно сохранять встроенные данные и saveKey каждой партии.
