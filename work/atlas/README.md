# АТЛАС: ядро, UI и расширения

Исходники раздельные. `python3 build.py` собирает их, стили и карту в один
`dist/index.html`, который не загружает внешних ресурсов. Для игры достаточно
скачать HTML и открыть его в браузере. npm-зависимостей нет.

Правила дальнейших изменений, сохранности партии и согласованный визуальный
стиль записаны в `AGENTS.md`. Пока новый стиль применяется к метаданным и дереву
статистики; перенос остальных окон будет отдельным этапом.

## Границы библиотек

| Часть | Файлы | Ответственность |
| --- | --- | --- |
| Ядро | `packages/core/index.js`, `packages/core/metadata.js` | Singleton игры, оригинал карты, индекс областей, параметры, метаданные тайлов, реестр считалок и API расчёта, реестр типов экшенов, исполнение, журнал, ветки, слияния, отмена и повтор. Работает в Node без DOM. |
| Базовые считалки | `packages/statistics/basic.js` | Подключаемая библиотека площади регионов и суммирования числовых статов. |
| UI | `packages/ui/` | Singleton интерфейса, карта, ввод, независимые слои, переносимые и изменяемые по размеру окна, вкладки, публичные деревья меню, жизненный цикл расширений. |
| Адаптеры браузера | `packages/platform/browser.js` | PNG, Web Worker индексатора, файлы, IndexedDB и миграция прежних партий. Не входят в headless-ядро. |
| Нации | `extensions/nations-model.js`, `extensions/nation-relations.js`, `extensions/nation-borders.js`, `extensions/nations.js` | Модель и экшены наций, взаимные войны, раскраска границ, информация и редакторы. |
| Просмотр истории | `extensions/history.js` | Только интерфейс к истории ядра: окна, команды меню, импорт/экспорт журналов. |
| Файлы | `extensions/files.js` | Интерфейс импорта/экспорта карт и партий. |
| Метаданные | `extensions/metadata.js` | Редактор записей тайла, выбор набора регионов и просмотр дерева статистики. |
| Ресурсы | `extensions/resources-model.js`, `extensions/resource-flow.js`, `extensions/resources.js` | Рецепты и ресурсные точки как метаданные, снабжение по приоритету, дерево выпуска, редакторы и пиксельные маркеры. |
| Запуск | `app.js` | Связывает библиотеки, подключает расширения и сохраняет партию. |

Ядро не зависит от UI, Canvas, браузерных адаптеров или расширений. Ни нации,
ни их цвета не зашиты в него. Библиотека UI не импортирует редактор наций или
просмотрщик истории. Модули подключаются через `ExtensionHost`.

Границы между провинциями одной нации окрашиваются в её цвет с RGB-каналами,
умноженными на 0,5 (округление до ближайшего целого). Например, `#517eaa`
превращается в `#293f55`. Внешние границы, побережья и границы свободных
территорий сохраняют исходный вид. Маски строятся по тёмным штрихам оригинала
карты и индексу, отдельно от заливки. Изменение владельца, цвета нации, ветки
или отмена действия обновляют соседние границы. Слой включается в PNG-экспорт
и удаляется вместе с расширением наций; геометрия и журнал ядра не меняются.

Растровые слои карты масштабируются с `image-rendering: pixelated`, без
сглаживания границ пикселей. Canvas-отрисовка и PNG-экспорт также отключают
интерполяцию изображений; текст и элементы интерфейса используют обычный рендеринг.

## Нации и войны

Кнопка `ⓘ` в списке наций открывает информацию о нации: число провинций,
состояние мира или войны и список противников. В этом окне можно выбрать новую
враждебную нацию и объявить войну либо заключить мир с любым противником.
Окно также доступно через меню «Мир» и контекстное меню принадлежащей нации провинции.

Война взаимна и хранится единственной записью в `meta.nations.wars`:
ключ — `JSON.stringify([nationId, enemyId].sort())`, значение — та же упорядоченная
пара ID. Исходные партии без этого поля считаются мирными. Удаление нации
одним экшеном освобождает провинции и убирает все её войны; отмена восстанавливает их.

```js
const model = new AtlasExtensions.NationsModel(AtlasCore.getGameState());
model.setWar('nation-1', 'nation-2', true);  // объявить взаимную войну
model.atWar('nation-2', 'nation-1');         // true
model.enemies('nation-1');                  // массив наций-противников
model.setWar('nation-1', 'nation-2', false); // заключить мир
```

Модель не зависит от DOM. Тип `nations.war.set` регистрируется при включении
расширения. Изменения исполняются ядром и попадают в его историю, ветки,
слияния, JSON и HTML. При отключении расширения журнал и отношения сохраняются.
Границы между воюющими нациями рисуются цветом `#ff3b30` тем же пиксельным слоем,
который рисует внутренние границы. Война имеет приоритет на стыке нескольких
провинций; берега и вода не закрашиваются. PNG содержит красные границы.

## Singleton состояния игры

```js
const game = AtlasCore.getGameState();

game.regionIndex; // RegionIndex: геометрия, at(x,y), idAt(x,y), маски областей
game.regions;    // ReadonlyMap<number, {id, bbox, anchor, area}>
game.originalMap; // {dataURL, width, height, name}; исходный PNG без перекраски
game.params;     // Обычно неизменяемые параметры игры, readonly JSON-снимок
game.meta;       // Расширяемые данные игры, readonly текущий JSON-снимок
game.actions;    // Реестр типов экшенов ядра
game.history;    // История экшенов и веток, принадлежащая ядру
game.tileMetadata; // Общий API записей провинций
game.statistics; // Реестр считалок и API расчёта по набору регионов

game.setMeta(['campaign', 'title'], 'Новая партия');
game.updateMeta('resources', draft => { draft.gold = (draft.gold || 0) + 10; });
game.updateParams(draft => { draft.ruleset = 'custom'; });
```

Метаданные доступны расширениям и могут часто меняться. Запись делается через
ядро, чтобы оно автоматически зарегистрировало экшен. Прямое изменение
`game.meta`, `game.params`, оригинала карты или геометрии запрещено: эти объекты
заморожены. Приватный пиксельный массив индекса наружу не выдаётся.

В ядре «регион» — одна индексируемая область карты (провинция). Нации и
пользовательские группы провинций хранятся в `meta.nations`, поскольку это данные
расширения. При миграции прежние группы остаются группами; ID провинций сохраняются.

## Метаданные провинций и дерево статистики

У каждой провинции может быть несколько записей с названием, описанием и статами.
Статы — JSON-объект: числа, строки, логические значения, массивы и вложенные объекты.
Идентификаторы `source` и `kind` позволяют расширению узнавать свои записи.
Все изменения записей выполняются экшенами ядра и поддерживают историю и ветки.

```js
const entryId = game.tileMetadata.save(42, {
  title: 'Промышленный район', description: 'Заметка к провинции',
  stats: { population: 1200, tags: ['industry'] }
});
game.tileMetadata.list(42);
game.tileMetadata.get(42, entryId);
game.tileMetadata.remove(42, entryId);
```

Ядро хранит реестр и запускает расчёт. Конкретные считалки регистрируются
библиотеками в singleton. В ядре нет встроенных формул площади или производства.
`app.js` отдельно подключает базовые считалки, ресурсный модуль — свою.

```js
const registration = game.statistics.register('my.population', {
  title: 'Население', keys: ['population'],
  collect({ values }) {
    return { children: [
      { id: 'totals', title: 'Итоги', children: [
        { id: 'population', title: 'Жители', unit: 'чел.',
          value: values('population').reduce((sum, row) => sum + Number(row.value), 0) }
      ] }
    ] };
  }
}, { signal: extensionScope.signal });

const result = game.statistics.calculate([42, 43, 44]);
result.tree; // Массив папок: по одной на успешно отработавшую считалку
result.get(['my.population', 'totals']); // Папка с children
result.value(['my.population', 'totals', 'population']); // Конкретное значение
result.value(['basic.geometry', 'area']); // Площадь набора в пикселях²
result.errors; // Ошибки отдельных считалок
registration.dispose();
```

`collect` и `calculate` — синонимы. Набор может быть произвольным; дубликаты ID
удаляются, неизвестные ID отклоняются. Контекст содержит `regionIds`, `regions`,
`allRegions`, `entries` (пары `{regionId, entry}`), `meta`, `params`, `values(key)`
и `handledKeys`. `order` определяет порядок считалок; заявленные `keys` успешной
считалки попадают в `handledKeys` следующих. Базовый сборщик числовых статов
суммирует только незаявленные ключи.

Каждый результат считалки превращается в папку с её ID и названием. Вложенный
узел имеет либо `children` (папка), либо `value` (лист); `unit` необязателен.
Ядро добавляет `type: 'folder' | 'stat'`. ID уникальны среди соседей, поэтому
путь — массив ID без привязки к названиям и локализации. Для отсутствующего
пути `get` возвращает `null`, `value` — `undefined`; для папки `value` также
возвращает `undefined`. Ноль остаётся корректным значением. Дерево заморожено,
сериализуется в JSON; методы поиска в JSON не входят.

Считалки синхронные и не изменяют игру. Исключение, некорректное дерево или
попытка записи состояния изолируются в `errors`, остальные продолжают работу.
Ограничение: 10000 узлов на считалку и глубина до 32. Отключение регистрации
через `dispose` или `AbortSignal` сохраняет метаданные и историю.

В интерфейсе меню «Данные» открывает редактор метаданных и статистику. Можно
считать текущую провинцию, вручную собранный набор или всю карту. Окно нации
позволяет передать в тот же API все её территории. Это интерфейсные расширения.

Режим «Набор регионов» включается в переключателе «Клик» сверху, кнопкой
«Набор на карте» в статистике или клавишей S. Клик добавляет/убирает провинцию,
Shift + клик только убирает. Esc или I возвращает обычный выбор. Кисть и ластик
при этом выключены: у карты всегда только один активный инструмент.

Кнопка ⊞ в строке нации добавляет все её текущие территории к существующему
набору. Повторное добавление не создаёт дубликатов. Та же команда есть в окне
информации о нации и контекстном меню её провинции. При добавлении нескольких
наций набор объединяет их территории, а не заменяет предыдущую нацию.

Набор выделяется бирюзовой заливкой и краем, сохраняя чёткие пиксели. Флажок
«Подсветка набора» скрывает её. Выбор набора и активный инструмент — временное
состояние UI: они не меняют владение, историю и экспортируемую карту PNG.
Выбранные ID остаются снимком набора; дальнейшая смена владельца не меняет набор.

## Производства и ресурсные точки

Отдельный модуль «Ресурсы и производства» создаёт обычные записи метаданных
с `source: 'resources'` и `kind: 'production' | 'resource-point'`. Они доступны
общему редактору. Производство задаёт ресурс, операцию (добыча, переработка,
производство), единицу, базовый выпуск, рецепт расхода и приоритет снабжения.
Точка задаёт фильтры и несколько баффов;
пустой фильтр означает любое значение. Точка собственного выпуска не имеет.

| Этап | Тип баффа | Действие |
| --- | --- | --- |
| 4 | `province-flat-total` | Число один раз к выпуску своей провинции |
| 4 | `province-flat-each` | Число каждому производству своей провинции |
| 2 | `province-percent` | Процент к выпуску своей провинции |
| 3 | `production-flat` | Число каждому производству переданного набора |
| 1 | `total-percent` | Процент ко всему выпуску переданного набора |
| 4 | `province-input-flat` | Снижение базового расхода числом у предприятий своей провинции |
| 2 | `province-input-percent` | Процентное снижение расхода в своей провинции |
| 3 | `global-input-flat` | Снижение базового расхода числом во всём наборе |
| 1 | `global-input-percent` | Процентное снижение расхода во всём наборе |

Баффы одного типа складываются. Общие баффы учитываются только от точек внутри
переданного набора. Ресурсы, операции и единицы считаются отдельными группами.
Провинциальный плоский бонус применяется один раз к каждой подходящей группе
в своей провинции, если там есть производства. Для каждой группы и провинции:

```text
после4 = база + провинциальный_бонус_к_итогу + число_производств × провинциальный_бонус_каждому
после2 = после4 × (1 + провинциальные_проценты / 100)
после3 = после2 + число_производств × общий_бонус_каждому
после1 = после3 × (1 + общие_проценты / 100)
```

Плоский бонус к итогу провинции распределяется между предприятиями группы
пропорционально их базовому выпуску; при нулевой общей базе — поровну.
Это сохраняет прежний итог группы и позволяет вычислить мощность каждого
предприятия отдельно. Все баффы увеличивают расход в той же пропорции, что выпуск.

### Рецепты и ограничение сырьём

В `stats['resource.inputs']` хранится массив `{resource, unit, amount}`.
`amount` — расход на полный базовый выпуск, а не расход на одну единицу продукта.
Например, выпуск 100 стали с расходом 200 железа задаёт соотношение 2:1.
При мощности 200 стали после баффов максимальный расход будет 400 железа.
С фактически доступными 100 железа завод выпустит 50 стали и потратит 100 железа.

```js
model.save(42, {
  title: 'Сталелитейный завод', kind: 'production',
  resource: 'Сталь', activity: 'processing', unit: 'т/ход', baseOutput: 100,
  priority: 0, inputs: [{ resource: 'Железо', unit: 'т/ход', amount: 200 }]
});
```

Рецепт может содержать несколько видов сырья. Ограничивает самый дефицитный вход.
Одинаковые ресурс и единица в повторных строках суммируются; разные единицы
не конвертируются автоматически. Названия ресурсов и единиц сопоставляются без
учёта регистра и крайних пробелов. Для рецепта с расходом нужна положительная база.
Прежние предприятия без полей рецепта считаются предприятиями без расходов.
Расходы, приоритет и изменения рецептов сохраняются в метаданных, истории и файлах.

Бонусы эффективности используют те же фильтры продукта, деятельности и единицы
выпуска, что бонусы мощности. Дополнительно каждый такой бонус может иметь
`inputResource` и `inputUnit` — фильтры расходуемого сырья; по умолчанию `'*'`.
В форме ресурсной точки поля этих фильтров появляются для типов снижения расхода.
Численные скидки уменьшают каждый подходящий базовый расход предприятия.
Порядок снижения: локальное число → локальный процент → общее число → общий
процент. Отрицательный результат обрезается до нуля. Проценты одного типа
складываются до 100%; проценты роста выпуска этим пределом не ограничены.

```text
после4 = max(0, базовый_расход − локальная_скидка)
после2 = после4 × max(0, 1 − локальные_проценты / 100)
после3 = max(0, после2 − общая_скидка)
расход_эффективного_рецепта = после3 × max(0, 1 − общие_проценты / 100)
максимальный_расход = расход_эффективного_рецепта × мощность_с_баффами / базовый_выпуск
фактический_расход = максимальный_расход × фактическая_загрузка
```

Сначала меняется базовый рецепт, затем весь эффективный рецепт масштабируется
выпуском. Поэтому численная скидка сохраняет эффект при росте мощности.
В «Потенциале» максимальное потребление уже учитывает эффективность; в дереве
бонусов показаны отдельные скидки, их точки и фильтры сырья.

Расчёт использует только предприятия переданного набора. Начальных запасов нет.
Предприятия без расходов дают исходное сырьё. Остальные получают доступные ресурсы
по приоритету: меньшее целое число раньше, затем номер провинции и порядок записей.
После выпуска поставщика первым снова проверяется самое приоритетное ожидающее
предприятие. Не хватает сырья — снижаются загрузка, выпуск и все расходы вместе.
Производитель не занимает будущие ресурсы; циклические рецепты без внешнего сырья
сами не запускаются. Очень длинная циклическая цепочка ограничена 50000 запусками
и возвращает явную ошибку вместо недостоверного результата. Это последовательное
снабжение по приоритетам; оно не ищет глобальный максимум выгоды набора.

### Дерево ресурсов

В папке считалки `resources` лежат:

- Листы ресурсов с положительным **чистым остатком**: фактический выпуск минус
  фактическое потребление. Полностью потраченное сырьё в корне не показывается.
- `gross` — «Грязное производство»: фактический выпуск до вычитания расходов,
  а также папка загрузки предприятий с выпуском и расходом каждого.
- `potential` — «Потенциал»: папка каждого ресурса с максимальным производством
  и максимальным потреблением при полной мощности с баффами, без ограничения сырьём.
- `bonuses` — «Бонусы»: папки базового производства и бонусов по ресурсам и типам;
  отдельные значения подписаны названием точки и номером провинции.

В снабжении и суммарном дереве один ресурс с одной единицей объединяется по всем
видам деятельности. Отдельные виды деятельности остаются фильтрами баффов.
ID ресурса строится через `resourceKey(resource, unit)`:

```js
const steel = AtlasExtensions.resourceKey('Сталь', 'т/ход');
const report = game.statistics.calculate([42, 43]);
report.value(['resources', steel]); // Чистый остаток; undefined, если он нулевой
report.value(['resources', 'gross', steel]); // Фактический выпуск без вычета
report.value(['resources', 'potential', steel, 'production']);
report.value(['resources', 'potential', steel, 'consumption']);
report.value(['resources', 'bonuses', 'base', steel]);
report.get('resources').allocation; // Мощности, загрузка, фактические расходы
```

Дополнительные поля папки `resources`: `resources` — балансы и потенциалы,
`allocation` — предприятия в порядке снабжения, `details` — прежняя детализация
мощностей по операциям и этапам 4→2→3→1. API расчёта и проверка дерева по-прежнему
принадлежат ядру; рецепты и распределение ресурсов реализует подключаемый модуль.

Маркеры: золотой завод — производство, бирюзовый ромб — ресурсная точка.
Они рисуются отдельным пиксельным слоем и входят в PNG. Отключение ресурсного
модуля убирает интерфейс, слой и его считалку; записи и история остаются.

## Экшены исполняет и регистрирует ядро

Расширение определяет обработчик типа, но не ведёт собственную историю:

```js
const registration = game.actions.register('economy.add', {
  label: 'Начисление ресурсов',
  reduce(draft, payload) {
    draft.meta.economy ||= { gold: 0 };
    draft.meta.economy.gold += payload.amount;
  }
}, { signal: extensionScope.signal });

const commit = game.dispatch('economy.add', { amount: 15 }, { source: 'economy' });

commit.action.id;      // Постоянный ID экшена
commit.action.type;    // 'economy.add'
commit.action.payload; // {amount: 15}
commit.actions;        // Вычисленные ядром изменения before/after
```

`dispatch` берёт снимок выбранной ветки, выполняет синхронный reducer над
черновиком, вычисляет изменения, проверяет данные и атомарно записывает коммит.
Ошибка, асинхронный reducer или вложенная запись состояния отклоняются целиком.
Reducer меняет только переданный черновик. Внешние эффекты и `await` выполняются
до вызова `dispatch`, а не внутри него.

Даже базовые `setMeta`, `updateMeta`, `deleteMeta` и `updateParams` создают
экшены ядра. Если фактических изменений нет, пустая запись не создаётся.

```js
game.history.actions;                 // Все записанные экшены
const action = game.history.getAction(commit.action.id);
action.patches;                       // Неизменяемые изменения before/after
game.history.revertAction(action.id); // Новый обратный экшен
game.history.applyAction(action.id);  // Повторное применение записанных изменений
game.history.undo();
game.history.redo();
```

Индивидуальное применение/обращение проверяет предыдущее значение каждого
поля. Если данные уже изменились, ядро возвращает конфликт вместо молчаливой
перезаписи. Отмена и повтор дописывают записи, сохраняя исходный журнал.

Экшен хранит тип, payload и готовые изменения. Поэтому ядро может восстановить
партию, слить ветку, применить или обратить записанный экшен даже после выгрузки
расширения, которое зарегистрировало его тип. Восстановление не исполняет код
расширений из файла журнала.

## Ветки, предложения изменений и слияние

```js
game.history.createBranch('proposal');

// Записать действие в отдельную ветку; актуальная main не меняется:
game.dispatch('economy.add', { amount: 20 }, { branch: 'proposal' });

game.history.snapshot('proposal');
game.history.previewMerge('proposal', { target: 'main' });
game.history.merge('proposal', { target: 'main' });

// Или открыть ветку для интерактивного редактирования на карте:
game.history.checkout('proposal');
game.history.checkout('main');
```

История — DAG коммитов с родителями и указателями веток. Слияние использует
общего предка и трёхстороннее сравнение. Независимые изменения объединяются;
разные изменения одного значения требуют решения. По умолчанию конфликт
ничего не применяет. Явные стратегии — `ours` и `theirs`.

Источник слияния не удаляется. Если целевая ветка не активна, её новая вершина
сохраняется в истории; актуальная игра изменится при переходе на эту ветку.
Слияние в активную ветку сразу обновляет singleton и отрисовку.

```js
const bundle = game.history.exportBranch('proposal');
game.history.importBranch(bundle, { name: 'friend-proposal' });
// Импорт сам по себе не меняет актуальное состояние.
game.history.merge('friend-proposal');
```

Журнал проверяется на принадлежность карте и исходной базе, связи коммитов,
циклы, дубликаты ID и корректность предшествующих значений. Несколько независимых
баз слияния при criss-cross истории явно отклоняются; для них нужна промежуточная
ветка. Массивы считаются атомарными значениями, объекты объединяются по полям.

История полностью принадлежит ядру. Отключение расширения «Ветки и журнал»
убирает только её просмотр и команды меню; запись экшенов продолжает работать.

## Публичные примитивы интерфейса

```js
const ui = AtlasUI.getUI();
ui.viewport; // Карта, камера, выбор области, независимые Canvas-слои
ui.windows;  // WindowManager
ui.mainMenu; // Публичный TreeMenu
ui.tileMenu; // Второй независимый TreeMenu с тем же API
ui.input;    // EventBus ввода
ui.tools;    // Реестр взаимоисключающих инструментов карты
ui.extensions;

const off = ui.input.on('province:click', ({ id, region, x, y }) => {});
ui.input.on('province:hover', event => {});
ui.input.on('province:context', event => {});
ui.input.on('selection:change', event => {});
off();
```

`x,y` — координаты оригинального изображения; `id`/`region` равны `null` на
море и границе. Перетаскивание и масштабирование не вызывают клик по провинции.

### Активные инструменты карты

Расширения регистрируют активные действия в UI, а не отдельные конкурирующие
обработчики раскраски на `province:click`:

```js
const registration = ui.tools.register({
  id: 'example:mark', label: 'Мой инструмент',
  click(event) { if (event.id) { /* Действие по клику на провинцию. */ } }
}, { signal: scope.signal });
registration.activate(); // Или ui.tools.activate('example:mark')
ui.tools.activeId;
ui.tools.reset(); // Нейтральный 'ui:select'
registration.dispose();
```

Реестр гарантирует один вызов активного инструмента на один клик. Общие события
ввода остаются доступны для наблюдения. Отключение активного расширения возвращает
инструмент «Выбор тайла», удаляя его из переключателя. Внутри `start(ctx)` можно
использовать `ctx.tool({id: 'mark', label, click})`: префикс и `AbortSignal`
добавляются автоматически. Подсказки `shortcut` выводятся в переключателе;
обработчики клавиш расширение подключает через `ctx.on('key', ...)`.

Для временных слоёв интерфейса доступно
`ctx.layer({id: 'selection', order: 80, exportable: false})`. Такой слой
масштабируется вместе с картой, но не входит в PNG.

Между расширениями доступны события UI: `statistics:open` с
`{regionIds, title}` заменяет набор, `statistics:add-regions` с `{regionIds}`
добавляет ID без дубликатов и включает режим набора. Модуль наций использует
второе событие и не зависит от внутренней реализации редактора метаданных.

### Один API для обоих деревьев меню

```js
const handler = new AtlasUI.ActionHandler(({ id }) => {
  // При изменении игры вызываем game.dispatch(...).
}, { signal: scope.signal });

const entry = ui.tileMenu.register({
  id: 'my-extension.example',
  path: ['Действия', 'Пример'],
  label: 'Выполнить',
  handler,
  when: context => !!context.id,
  enabled: context => context.id !== null
});

handler.disable(); // Удалит все пункты, подписанные на этот обработчик
entry.dispose();   // Удалит только эту регистрацию
```

Удаление последнего пункта автоматически убирает пустые группы. `AbortSignal`
снимает регистрацию; отключение всего расширения снимает все его регистрации.
`enabled: false` показывает недоступную кнопку, а `handler.disable()` завершает
жизненный цикл обработчика и удаляет кнопку. Это разные операции.

Можно создать собственное дерево:

```js
const menu = new AtlasUI.TreeMenu();
menu.register({ id: 'a', label: 'Действие', handler: () => {} });
menu.open({ x: 100, y: 100, context: { id: 42 } });
menu.close();
menu.dispose();
```

`ActionHandler` — обработчик UI, а не запись игрового экшена. Он вызывает
`game.dispatch` или базовые методы ядра; запись игры выполняется уже ядром.

### Общие списки и деревья данных

`packages/ui/data-view.js` предоставляет предметно-независимые примитивы.
Расширение явно добавляет контейнеру класс `atlas-data-scope`, поэтому остальные
окна сохраняют свои стили. Шрифт и размер всех элементов области едины; строки
имеют шаг 16 px, длинный текст полностью переносится на 32, 48 и более px.
Одинарная линия соединяет название со значением, двойная обозначает категорию.
Группы используют native `details/summary` без треугольника и одинаково меняют
цвет при сворачивании. Отступ каждого уровня — 21 px.

```js
const { createDataRow, createDataGroup, renderDataTree } = AtlasUI.dataView;
pane.classList.add('atlas-data-scope');
const group = createDataGroup('Запись', { open: true });
group.body.append(createDataRow('Население', '124 000'));
pane.append(group.element);

// Хранить Map в области окна, чтобы пересчёт сохранял раскрытые группы.
const expanded = new Map();
renderDataTree(pane, report.tree, {
  expanded,
  formatValue: node => String(node.value) + (node.unit ? ' ' + node.unit : '')
});
```

Данные вставляются через `textContent`. Идентификаторы путей папок отделены от
названий. Эти компоненты используются просмотром метаданных и статистики;
редактор записей использует те же типографику и вертикальный шаг.

### Окна и вкладки

```js
const tab = ui.windows.open({
  id: 'my-tab', windowId: 'my-window', title: 'Инструмент',
  x: 20, y: 20, width: 280, height: 320,
  signal: extensionScope.signal,
  render(pane, tabScope, handle) {
    pane.textContent = 'Содержимое';
    ui.input.on('province:click', event => {
      pane.textContent = 'Провинция #' + event.id;
    }, { signal: tabScope.signal });
  }
});

tab.activate();
ui.windows.moveTab(tab.id, anotherTab.windowId);
ui.windows.merge(tab.windowId, anotherTab.windowId);
ui.windows.resize(tab.windowId, 400, 300);
tab.close();
```

Окна перемещаются за заголовок или `⠿`, меняют размер за нижний правый угол.
При отпускании окна над другим окном их вкладки объединяются. Отдельную вкладку
можно перетащить в другое окно или вынести на карту. Содержимое при переносе
остаётся тем же DOM-узлом и не подписывается на события повторно.

Закрытие вкладки освобождает её локальный `tabScope`. Закрытие последней вкладки
автоматически удаляет окно. Если в одном окне смешаны вкладки разных расширений,
выгрузка расширения закрывает только принадлежащие ему вкладки.

## Контракт расширения

```js
ui.extensions.register({
  id: 'example', name: 'Пример', description: 'Мой модуль',
  start(ctx) {
    ctx.state.actions.register('example.note', {
      label: 'Заметка к провинции',
      reduce(draft, { id }) {
        draft.meta.example ||= { notes: {} };
        draft.meta.example.notes[id] = 'Отмечено';
      }
    }, { signal: ctx.signal });

    ctx.menu(ctx.ui.tileMenu, {
      id: 'note', path: ['Пример'], label: 'Отметить',
      when: event => !!event.id,
      handler: ({ id }) => ctx.state.dispatch('example.note', { id })
    });

    ctx.on('province:click', event => console.log(event.id));
    ctx.window({ id: 'tool', title: 'Мой инструмент', render: pane => {
      pane.textContent = 'Панель расширения';
    }});
    // return () => ...; // Необязательная дополнительная очистка
  }
});

await ui.extensions.enable('example');
ui.extensions.disable('example');
```

Контекст даёт `state`, `ui`, `signal`, `scope`, `on`, `action`, `menu`, `window`,
`layer`, `tool`. Регистрации меню, инструменты, окна, слои и подписки, созданные через контекст,
автоматически принадлежат расширению. ID меню/вкладок получают его префикс.
Ручные регистрации в ядре и публичных объектах нужно привязывать к `ctx.signal`.

Камера, положение окон и вкладки — состояние интерфейса, а не игровые экшены.
Данные партии, включая исходный PNG и журнал, сохраняются через `state.toJSON()`.

## Сборка и проверки

```sh
python3 build.py
node --test tests/*.test.cjs
```

Для обычной сборки достаточно Python: оригинал включён в `assets/`.
Необязательная повторная подготовка карты через `preprocess.py` требует Pillow,
NumPy и SciPy. Новые карты в интерфейсе разбираются локально в Web Worker.

Исходная карта содержит 4587 отдельных четырёхсвязных областей серой суши.
Разрыв границы объединяет области, а несвязанные острова получают разные ID.
Географическое распознавание и сетевой multiplayer в эту архитектуру не входят.

Проверено: headless singleton, неизменяемость состояния, экшены и их адресация,
атомарность reducer-ов, ветки, конфликты и слияния, обмен журналами, отмена/повтор,
отключение обработчиков меню и миграция прежних партий. 58 автоматических проверок
также покрывают метаданные, реестр считалок, вложенные деревья, поиск по путям,
изоляцию ошибок, жизненный цикл регистраций, фильтры ресурсов, порядок баффов
и исключительное выполнение активного инструмента карты. Проверены ограничение
несколькими видами сырья, цепочки поставок, циклы, порядок снабжения, масштабирование
расхода баффами и сохранение ресурсных балансов при повторных расчётах. Проверены
четыре вида эффективности, порядок скидок, фильтры сырья, локальная область
действия, предел 100% и отсутствие отрицательного расхода.
В браузере проверены
слияние и разделение окон, ресайз, закрытие последней вкладки, выгрузка и повторный
запуск модулей, запись экшенов с отключённым просмотрщиком, контекстное дерево,
редакторы заметок, производств и нескольких баффов, восстановление после перезагрузки,
вложенные итоги и экспорт PNG/JSON/HTML. Проверены точные цвета PNG, ресурсные
маркеры, сохранность байтов оригинала и совпадение журнала в экспортах HTML и JSON.
Автоматический браузер не разрешает `file://`; прямое открытие автономного файла
им не проверялось. Собранный HTML не содержит внешних скриптов, стилей или изображений.
